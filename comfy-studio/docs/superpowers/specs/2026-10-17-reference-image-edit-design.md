# 참조 이미지로 이어 만들기

상태: 설계 검토 대기. 앱 코드 변경·모델 다운로드·실제 편집 생성은 아직 실행하지 않았다.

## 목적과 승인된 화면 흐름

사용자는 생성한 인물의 얼굴 특징을 유지하면서 배경·포즈·행동을 바꾼 이미지를 만들고 싶어 한다.
앞서 제안한 ‘이미지 편집’ 모드, 결과의 ‘이 이미지로 이어 만들기’, 직접 사진 업로드,
참조 이미지와 변경 요청, 사이즈만 보여주는 흐름을 사용자가 승인했다.
기존 어두운 색상·라임 포인트와 모바일 반응형 화면을 유지한다.
스텝·CFG·노이즈 강도 등은 저장된 워크플로 설정으로 처리한다.

## 방식 비교와 선택

1. 기존 생성 모델에 일반 img2img를 연결: 추가 다운로드는 줄지만 인물 특징을 보존하며
   포즈·배경을 크게 바꾸는 목적에 한계가 있어 이번 편집 모드의 기본 방식으로 쓰지 않는다.
2. 로컬 Qwen-Image-Edit-2511 참조 편집: 이미지와 변경 지시를 함께 입력할 수 있고,
   공식 모델 설명이 인물 일관성 개선을 명시한다. 이번 기능의 권장 방식이다.
3. 외부 이미지 편집 API: 별도 비용·서비스 설정과 이미지 외부 전송이 필요해 이번 범위에서 제외한다.

인물 유지는 참조 모델과 보존 지시를 이용하는 방식이며, 얼굴을 고정하는 보증이나
별도 얼굴 인식·인물 LoRA 학습 기능은 아니다. 큰 시점·포즈 변화에서는 인물이 달라질 수 있다.

## 모델·라이선스·하드웨어 확인

2026-10-17 확인 결과:

- GPU: RTX 3090, VRAM 24,576MiB 중 사용 21,086MiB, 여유 3,240MiB.
- 시스템 RAM: 63.9GiB 중 여유 약 39.9GiB. C 드라이브 여유 약 1.41TiB.
- 확인 시 ComfyUI 실행 중 작업과 대기 작업은 모두 0개. GPU 사용량만으로 다른 점유 주체까지 단정하지 않는다.
- Qwen 편집 노드 `TextEncodeQwenImageEditPlus`, 이미지 입력/리사이즈 및 샘플링 핵심 노드가 설치돼 있다.
- 편집용 diffusion checkpoint와 해당 편집 버전의 Lightning LoRA는 설치돼 있지 않다.
- 기존 `qwen_2.5_vl_7b_fp8_scaled.safetensors` 8.74GiB,
  `qwen_image_vae.safetensors` 0.24GiB를 재사용한다.

추가 파일:

| 파일 | 출처 | 크기 | 라이선스 |
|---|---|---|---|
| `qwen_image_edit_2511_fp8mixed.safetensors` | Comfy-Org/Qwen-Image-Edit_ComfyUI | 약 19.12GiB / 20.5GB | Apache-2.0 |
| `Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors` | lightx2v/Qwen-Image-Edit-2511-Lightning | 약 0.79GiB / 0.85GB | Apache-2.0 |

추가 다운로드는 합계 약 21.4GB다. 기존 T2I Qwen 2512 체크포인트나 LoRA를 편집 모델로 대신 사용하지 않는다.
파일 크기는 실제 실행 VRAM 사용량이 아니다. 모델·인코더·VAE·참조 이미지 활성값이 함께 필요하므로
24GB GPU에서도 전체 동시 상주를 전제로 하지 않고 ComfyUI의 메모리 관리와 CPU 오프로딩을 사용한다.
배치 1장, 출력 약 1MP부터 실제 메모리와 결과를 검증한다. 속도·실행 성공·인물 보존을 사전에 보장하지 않는다.
다운로드 직전에 GPU/RAM/디스크와 작업 큐를 다시 확인하고, 실행 중 작업을 취소하지 않는다.
부족할 때는 다른 모델을 몰래 적용하거나 사용자 설정을 임의로 낮추지 않고 원인을 표시한다.
파일 다운로드는 재개 가능한 임시 파일로 받고, 공식 메타데이터의 크기/해시와 대조 후 확정한다.
모델 파일은 Git에 넣지 않는다. 새로 확인한 라이선스는 루트 AGENTS.md 허용 표에 기록한다.

## 화면 동작

- 생성 설정 상단에 ‘이미지 생성 / 이미지 편집’ 전환을 둔다. 첫 진입은 기존 이미지 생성 모드다.
- 생성 모드에는 기존 3개 생성 모델, 편집 모드에는 편집용 Qwen 모델만 표시한다.
  상업 이용 가능 표시와 설치/사용 불가 사유를 기존 커스텀 모델 선택창으로 제공한다.
- 결과가 완성되면 ‘이 이미지로 이어 만들기’ 버튼을 제공한다. 누르면 현재 결과를 참조로 등록하고
  편집 모드로 전환하며 변경 요청 입력창으로 이동한다. 이전 생성 프롬프트를 편집 명령으로 자동 재사용하지 않는다.
- 편집 모드는 직접 업로드 또는 기존 결과에서 가져온 참조 이미지 1장을 보여준다.
  썸네일·교체·제거, ‘인물 특징 유지’ 기본 켜짐, 변경할 내용, 추천 사이즈를 표시한다.
- 인물 특징 유지는 참조 이미지를 실제 모델 입력으로 연결하고, 켜져 있으면 얼굴 특징을 보존하는 지시를 추가한다.
  끄면 해당 보존 지시만 추가하지 않는다. 참조 이미지는 계속 사용한다.
- 원본과 편집 결과를 각각 확인/확대할 수 있고 결과를 다운로드하거나 다시 참조로 사용할 수 있다.
- 편집 모드의 프롬프트와 참조 상태는 생성 모드와 분리한다. 작업 중에는 모드·참조·입력 변경을 잠근다.
- 참조 업로드 중, 유효성 오류, 모델 누락, 서버 연결 끊김을 구분해 표시한다.
  참조가 준비되지 않았거나 편집 모델이 없으면 편집 생성 버튼을 비활성화한다.

## 참조 이미지 저장과 API

- 새 참조 업로드/가져오기/조회 API는 기존 로그인 인증과 같은 출처 검사로 보호한다.
- 업로드는 PNG/JPEG/WebP 1장, 파일 최대 10MiB, 디코딩 최대 25MP로 제한한다.
  요청 본문을 읽는 단계에서도 상한을 적용해 Content-Length만 신뢰하지 않는다.
- 이미지 디코더로 실제 형식·손상을 검사하고 EXIF 회전을 반영한다.
  긴 변 최대 1536px로 비율을 유지해 정규화하고 메타데이터를 제거한 PNG로 저장한다.
  비율을 바꾸는 강제 자르기는 하지 않는다. 이미지 처리에는 명시적인 sharp 의존성을 사용한다.
- 참조 파일과 메타데이터는 `.data/references`에 서버가 발급한 UUID로 저장한다.
  사용자 파일명을 경로로 쓰거나 임의 URL/로컬 경로를 입력으로 받지 않는다.
  미리보기도 인증된 참조 이미지 API를 거친다.
- ‘이어 만들기’는 완료된 작업 ID와 결과 인덱스를 서버가 확인한 뒤 이미지 데이터를 복사해 같은 정규화 경로를 사용한다.
  클라이언트가 보낸 ComfyUI 파일 경로를 신뢰하지 않는다.
- API 응답은 참조 ID·정규화된 크기·인증된 미리보기 경로만 반환한다.
- 참조 ID는 생성 요청/작업 기록에 포함한다. 서버 재시작 후에도 같은 작업과 원본을 복원한다.
  참조 파일은 작업에서 사용할 수 있도록 이번 버전에서 자동 만료/정리하지 않는다. 저장 위치와 관리 방법을 문서화한다.

## 생성·워크플로 연결

- 기존 생성 작업과 조회/복구/다운로드 API를 확장해 편집도 같은 큐와 복구 체계를 사용한다.
- 편집 모델 ID와 참조 ID·인물 보존 여부를 검증한다. 편집 요청에는 참조가 필수이며,
  생성 요청에는 편집 전용 설정을 허용하지 않는다. 기존 저장 작업은 기존 형식 그대로 읽힌다.
- 공식 2511 템플릿을 토대로 단일 참조용 저장 워크플로를 만든다.
  새 편집 기본값은 Lightning 4-step 구성에 맞춰 고정하며 원본 템플릿의 40-step 기본 경로와 혼동하지 않는다.
  기존 3개 생성 워크플로의 샘플링 값을 변경하지 않는다.
- 요청별로 변경 가능한 값은 참조 이미지 입력, 편집 지시, 출력 크기, 랜덤 시드뿐이다.
  프롬프트 입력을 그래프 전체나 파일 경로로 해석하지 않는다.
- 정규화된 참조를 서버에서 ComfyUI input 하위 앱 전용 폴더로 전송하고,
  실제 `LoadImage` → 편집 인코더 참조 입력에 연결한다. 출력 잠재 크기는 선택한 출력 사이즈를 사용한다.
- 그래프 노드/필수 입력/모델 파일 검증을 통과한 경우에만 제출한다.
  UI에 편집 버튼만 추가하고 텍스트 생성으로 우회하는 동작은 허용하지 않는다.
- 기존 작업 UUID 기반 중복 제출 방지와 접수 유실 복구를 유지한다.
  참조 업로드 단계의 재시도는 앱이 소유한 UUID 파일에 대해 일관된 참조를 사용해야 한다.

## 검증과 완료 조건

1. 요청 검증: 참조 없는 편집, 생성 모드에 편집 설정, 알 수 없는 참조·파일 경로를 차단한다.
2. 업로드 검증: 지원 형식·용량·픽셀 제한·손상 파일·EXIF·메타데이터 제거·잘못된 UUID·비인증 요청을 확인한다.
3. 워크플로 검증: 저장된 샘플링 설정 보존, 참조 노드 연결, 편집 명령과 크기 반영, 모델 누락 처리를 확인한다.
4. 복구 검증: 기존 작업 호환, 편집 작업 중복 제출, 요청 유실, 서버 재시작 뒤 참조/작업 복원을 확인한다.
5. PC/모바일 브라우저: 업로드 → 변경 요청 → 생성, 결과 → 이어 만들기,
   참조 교체/제거, 모드 전환과 입력 잠금, 원본/결과 확인, 다운로드를 검사한다.
6. 상업용 허용 모델로 만든 기존 인물 이미지로 배경·행동 변경 편집을 최소 1회 실제 실행한다.
   원본/결과를 육안 비교하고 인물 특징과 변경 지시 반영 여부를 구분해 보고한다.
   작업 ID·실행 시간·피크 GPU/RAM을 기록한다. 얼굴이 완전히 동일하다고 과장하지 않는다.
7. 테스트·타입 검사·변경 파일 린트·프로덕션 빌드와 독립 코드 리뷰 후 PM2 서버를 갱신한다.
8. 기존 요청대로 커밋·푸시·PR·main 병합까지 처리하고 공개 주소에서 인증과 편집 UI를 확인한다.
   실제 비밀번호·참조/결과 원본·모델 파일은 Git에 포함하지 않는다.
