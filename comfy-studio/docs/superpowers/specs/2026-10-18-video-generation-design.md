# 영상 생성 메뉴

상태: 사용자 요구 범위 확인 완료. 작성된 설계 검토 대기.

## 목적과 확인된 요구

사용자는 Comfy Studio의 비활성 영상 생성 메뉴를 실제 사용할 수 있게 구현하고 싶어 한다.
2026-10-18 질문에 텍스트 → 영상과 이미지 → 영상 두 방식 모두를 선택했다.
기존 이미지 스튜디오와 같은 어두운 화면, 모바일 사용, 로그인, 작업 복구,
한 번 접수한 요청의 중복 실행 방지를 유지한다.

성공 기준은 프롬프트 또는 참조 이미지와 동작 설명을 입력해 로컬 ComfyUI에서 영상을 만들고,
사이트에서 소리와 함께 재생하고 MP4로 다운로드하는 것이다. 이미지 결과에서도 영상으로 이어 만들 수 있다.

## 접근 방식과 선택

1. 설치된 MiniMax H3를 기존 ComfyUI 서버에 연결한다. 이미 로컬 모델·노드·영상 워크플로가 있고
   사용자에게 상업 사용 허가가 있으므로 이 방식을 사용한다. PC에서 생성하므로 실행 시간과 메모리는 실제 검증한다.
2. 외부 영상 API는 별도 서비스 설정·과금·참조 사진 외부 전송이 수반된다.
3. 다른 로컬 모델로 교체하면 새로운 라이선스·다운로드·설치 및 별도 하드웨어 검증이 필요하다.

이번 설계는 1번을 기준으로 한다. 추가 모델 다운로드는 필요하지 않은 상태로 확인했다.

## 모델, 저장 워크플로, 현재 자원

루트 AGENTS.md에 기록된 MiniMax H3의 사용자 별도 상업 사용 허가를 적용한다.
다른 이미지 생성 모델은 이번 영상 기능의 모델 목록에 추가하지 않는다.

설치 상태를 2026-10-18 로컬 파일과 실행 중인 ComfyUI 노드 스키마로 확인했다.

- `MiniMax-H3-T2V-7s-Single-Shot.json`: 기본 출력 864×480, 목표 길이 7초.
- `MiniMax-H3-I2V-7s-RTX3090.json`: 참조 이미지 입력, 저장 출력 1344×768, 목표 길이 7초.
- diffusion 모델: `minimax_h3_fl2va_pruned_int8_convrot.safetensors` 약 20.97GB.
- 텍스트 인코더: `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`.
- 영상 VAE: int8 ConvRot 및 fp16 버전, 오디오 VAE: fp32 버전이 설치되어 있다.
- 핵심 노드: `MiniMaxH3ImageToVideo`, `CreateVideo`, `SaveVideo`, `VAEDecodeAudio`가 사용 가능하다.
- 두 워크플로는 subgraph 안에 H3 인코딩, 샘플링, 영상·오디오 디코딩을 포함한다.

확인 시 RTX 3090 VRAM은 24,576MiB 중 약 19,655MiB 사용, 약 4,671MiB 여유였다.
시스템 RAM은 약 63.9GiB 중 40.8GiB 여유, 디스크는 약 1.53TB 여유였다.
ComfyUI 실행 큐와 대기 큐는 모두 0건이었다. 자원 수치는 실행 직전에 다시 확인한다.
현재 VRAM 사용량만으로 다른 프로세스의 점유를 추정하거나 종료하지 않는다.

첫 버전은 두 모드 모두 864×480, 24fps, 목표 7초, 배치 1로 시작한다.
이는 T2V의 저장된 출력 크기를 기준으로 하고 I2V에도 동일한 낮은 해상도를 적용하는 명시적 설계 선택이다.
H3 프레임 수는 저장 워크플로의 `17k+5` 규칙을 적용한다. 목표 7초는 175프레임으로
실제 길이는 약 7.29초이므로 화면에는 ‘약 7초’로 표시한다.
샘플러·스텝·가속 스위치·모델·VAE는 각각의 저장 워크플로에서 읽는다.
가속 스위치가 꺼져 있으면 해당 LoRA를 실행 그래프에 포함하지 않는다.
새 LoRA를 활성화하거나 파일을 바꾸는 경우 먼저 라이선스를 확인한다.

ComfyUI의 모델 관리와 오프로딩을 사용한다. 파일 크기를 실제 VRAM 요구량으로 간주하지 않는다.
생성 전 자원을 다시 확인하고 실패나 메모리 부족 시 오류를 표시한다.
실패 후 다른 설정으로 자동 재생성하지 않는다.

## 사용자 화면과 흐름

- 상단 ‘영상 생성’ 메뉴를 `/video` 링크로 활성화하고 현재 메뉴를 표시한다.
- 이미지 스튜디오의 입력·진행 중 작업·결과는 영상 스튜디오와 따로 보존한다.
- 영상 페이지에는 ‘텍스트로 만들기 / 이미지로 만들기’ 전환, MiniMax H3 모델 안내,
  장면·동작·카메라·소리를 적는 프롬프트, 고정된 출력 크기와 약 7초 안내, 생성 버튼을 둔다.
- 이미지 모드에서는 PNG/JPEG/WebP 한 장을 업로드하거나 기존 생성 결과를 가져온다.
  현재 참조 이미지의 미리보기·교체·제거를 제공하고 참조가 없으면 생성 버튼을 잠근다.
- 이미지 결과에 ‘이 이미지로 영상 만들기’ 동작을 추가한다. 클릭하면 인증된 이미지 결과를
  기존 참조 저장 서비스로 등록하고 영상의 이미지 모드로 이동한다.
  이전 이미지 생성 프롬프트를 영상 동작 설명으로 자동 재사용하지 않는다.
- 생성 중에는 경과 시간과 요청 중·대기 중·생성 중 상태를 표시한다. 알 수 없는 진행률이나 예상 완료 시간을 만들지 않는다.
- 결과는 `video` 요소의 기본 controls로 재생·일시정지·음량·전체화면을 제공한다.
  자동 재생을 강제하지 않고 생성된 오디오를 그대로 포함한다.
- MP4 다운로드 버튼과 사용자 원문 프롬프트를 표시한다.
- 모바일 화면에서는 입력과 결과를 세로로 배치하고 터치 조작과 16px 이상 입력 글자를 유지한다.

## 프롬프트와 참조 입력

프롬프트는 기존과 같은 최대 8,000자로 제한한다. Google Translation 전용 계정으로 영어 번역 후
H3에 전달하고 화면·작업 기록에는 원문을 보존한다. 원문이 영어로 감지되면 그대로 사용한다.
번역된 내용에 포함된 대사 언어까지 원문으로 유지하는 별도 기능은 첫 버전의 요구가 아니다.
프롬프트 텍스트가 Google 번역에 전송됨을 표시한다. 참조 사진은 로컬 ComfyUI에만 전송한다.

참조 입력은 기존 10MiB·25MP 제한, 회전 정규화, EXIF 제거, 안전한 UUID 저장을 재사용한다.
기존 생성 결과는 완료된 이미지 작업만 허용한다. 서버가 검증한 참조 UUID만 실행 입력으로 허용한다.

## 데이터와 서버 경계

기존 이미지 작업의 데이터 형식과 경로는 유지한다. 영상 전용 타입·검증·저장·결과 조회를 추가한다.
공유할 부분은 기존 인증·번역·참조 저장·ComfyUI 통신 규칙이며 이미지 작업 전체를 재설계하지 않는다.

영상 입력은 모드(`text` 또는 `image`), 원문 프롬프트, 이미지 모드의 참조 UUID로 구성한다.
클라이언트가 체크포인트, 저장 경로, 샘플러, 프레임 수 등 임의의 실행 그래프 값을 보낼 수 없게 한다.
영상 작업은 `.data/video-jobs`에 UUID별로 저장하고 ComfyUI prompt ID, 상태,
출력 참조, 원문, 해상도, fps와 프레임 수를 기록한다.
브라우저는 영상 전용 localStorage 키로 현재 작업·마지막 결과를 복구한다.

API:

- `GET /api/videos/models`: ComfyUI 연결과 필요한 노드·파일·저장 워크플로의 사용 가능 여부.
- `POST /api/videos`: 입력 검증, Idempotency-Key 요구, 작업 생성·번역·참조 업로드·ComfyUI 제출.
- `GET /api/videos/[id]`: 상태 조회와 제출 후 연결 오류 복구.
- `GET /api/videos/[id]/media`: 완료된 해당 작업의 MP4만 재생·다운로드.

모든 API는 Proxy와 데이터 처리 경계에서 로그인 인증을 적용한다.
POST에는 기존 같은 출처 검사와 요청 크기 제한을 적용한다.
작업별 잠금과 최초 원문 입력 저장 후 번역·제출을 수행한다.
동일 UUID·동일 입력은 기존 작업을 반환하고 다른 입력은 409로 거부한다.
번역·모델·참조 준비 실패는 `/prompt` 제출 전에 실패 상태로 확정한다.
접수 여부가 불명확하면 같은 UUID의 큐·실행 기록을 찾아 복구하며 자동 재제출하지 않는다.

영상 실행 그래프는 두 등록된 저장 워크플로를 읽어 subgraph와 스위치를 해석한다.
서버는 프롬프트, 참조 이미지, 승인된 출력 크기·길이, 요청별 시드, 안전한 출력 접두사만 바꾼다.
저장된 가속 분기와 샘플링 설정 보존을 테스트한다.
T2V는 H3의 optional first_frame 없이 실행하며 I2V는 정규 참조 사진을 first_frame에 연결한다.
`CreateVideo`의 오디오 연결을 유지하고 `SaveVideo`에서 MP4/H.264를 명시한다.

## 재생·다운로드와 저장 보안

ComfyUI `SaveVideo`의 실제 실행 기록 형식을 확인하여 영상 출력 참조를 추출한다.
출력 확장자는 MP4, type은 output으로 제한하며 파일명·하위 폴더의 경로 탈출을 거부한다.
사용자 입력 경로로 파일을 직접 읽는 API를 제공하지 않는다.
완료된 작업에 저장된 출력 참조로만 ComfyUI `/view`를 호출한다.

브라우저 탐색과 모바일 재생을 위해 인증된 미디어 API에서 Range 요청을 전달하고
upstream의 200·206·416과 Content-Range·Accept-Ranges·Content-Length를 올바르게 처리한다.
영상 응답을 서버 메모리에 전부 모으지 않고 스트리밍한다.
`video/mp4`, `no-store`, `nosniff` 및 안전한 Content-Disposition을 적용한다.
서비스 워커는 로그인·영상·참조·작업 API를 캐시하지 않는다.
영상과 참조는 기존과 같이 자동 삭제하지 않으며 로컬 디스크 사용을 관리해야 한다.

## 오류와 복구

ComfyUI 연결 끊김, 모델·노드 누락, 참조 준비 오류, 번역 오류, 메모리 부족,
생성 실패, 미디어 조회 실패를 사용자가 구분할 수 있는 메시지로 표시한다.
워크플로가 예상 구조와 다르거나 저장 노드가 없으면 사용 불가 사유를 표시하고 제출을 막는다.
연결이 끊겨도 접수된 작업의 번호를 유지하며 새 요청을 자동 생성하지 않는다.
이미지·영상 요청은 같은 ComfyUI 서버의 큐에서 순서대로 실행된다.
기존 큐를 지우거나 사용자 작업을 취소하지 않는다.

## 검증과 적용 기준

자동 검사:

- 영상 입력 검증과 모드별 참조 필수 조건, 경로·확장자 검증.
- 저장 워크플로의 모델·VAE·샘플러·스위치 보존과 프레임 규칙.
- T2V first_frame 미포함, I2V 정규 참조 연결, 오디오 포함 및 MP4 출력.
- 원문 보존, 번역 실패 시 미제출, 중복 요청 시 단 한 번 제출, 연결 오류 후 작업 복구.
- 인증·같은 출처·요청 크기 제한, Range 스트리밍 상태와 헤더 처리.
- 기존 이미지 테스트 전체, 타입 검사, lint, 프로덕션 빌드.

실제 검증:

- 실행 직전 GPU·RAM·디스크·큐를 다시 확인한다.
- 텍스트 → 영상 1건과 상업 사용 가능한 기존 참조 사진의 이미지 → 영상 1건을 실행한다.
- ComfyUI에 전달된 번역·참조, 원문 기록, 생성 길이·해상도·영상·오디오 스트림을 확인한다.
- 데스크톱과 모바일 화면에서 메뉴 전환·참조 입력·상태 복구·영상 재생·MP4 다운로드를 확인한다.
- 사이트의 인증된 미디어와 Range 응답, 비로그인 차단을 확인한다.
- 기존 이미지 생성 흐름을 회귀 검사한다.

구현과 실제 검증을 마친 뒤 검토 가능한 PR로 제공한다.
운영 적용 시 기존 빌드를 백업하고 comfy-studio만 교체·재시작하며 외부 HTTPS에서 최종 확인한다.
이 설계 문서 승인 후 구현 계획을 작성하고, 계획의 실행 방식을 정한 뒤 제품 코드를 변경한다.
