# Comfy Studio — 이미지 생성 설계

작성일: 2026-10-17

## 목적과 승인된 방향

사용자는 이미 설치한 ComfyUI를 간단한 Next.js 화면에서 사용하려 한다.
메뉴는 이미지 생성, 영상 생성, 노래 생성이며 이번 구현 대상은 이미지 생성이다.
사용자는 모델, 프롬프트, 출력 크기만 선택한다. 샘플러, 스텝, CFG,
인코더, VAE, LoRA와 모델별 기능 스위치는 저장된 워크플로의 값을 사용한다.

사용자가 승인한 화면 방향은 밝은 아이보리 배경, 짙은 글자, 라임 포인트다.
PC에서는 메뉴 / 생성 입력 / 결과를 배치하고 모바일에서는 세로로 정렬한다.

프로젝트: `C:\ComfyUI\comfy-studio`.
기존 Next.js 16.4.2 / React 19.3.0 / TypeScript / Tailwind 4 설치를 사용한다.
새 프로젝트나 외부 호스팅을 만들지 않는다.

## 이번 작업 범위

- 이미지 생성 화면과 로컬 ComfyUI 실제 연동.
- 세 가지 설치 모델의 프리셋 선택, 모델별 추천 사이즈, 프롬프트 입력.
- 생성 요청, 대기/생성/완료/실패 상태, 결과 이미지, 다운로드.
- 다른 두 메뉴는 준비 중 상태를 명확히 표시한다.
- 외부 도메인, 터널 변경, 로그인 및 영상/음악 생성은 별도 후속 작업이다.
  이번 개발 서버는 루프백 주소에서만 실행한다.

## 확인된 환경

GPU는 RTX 3090 24 GiB이며 이번 확인 시 가용 VRAM은 22,270 MiB였다.
이는 실시간으로 변하므로 실제 생성 시험 전에 다시 확인한다.
ComfyUI 주소 기본값은 `http://127.0.0.1:8188`이다.

설치 파일과 프로젝트 상업용 허용 목록을 대조한 초기 이미지 모델:

| 표시 이름 | 저장 워크플로 | 주요 설치 파일 |
| --- | --- | --- |
| Z-Image Turbo | `T2I_Z-Image-Turbo.json` | `z_image_turbo_bf16.safetensors`, `qwen_3_4b.safetensors`, `ae.safetensors` |
| Qwen Image 2512 | `T2I_Qwen-Image-2512.json` | `qwen_image_2512_fp8_e4m3fn.safetensors`, `qwen_2.5_vl_7b_fp8_scaled.safetensors`, `qwen_image_vae.safetensors`, 저장된 Lightning LoRA |
| Krea 2 Turbo | `Krea2-Turbo-RTX3090.json` | `krea2_turbo_fp8_scaled.safetensors`, `qwen3vl_4b_fp8_scaled.safetensors`, `qwen_image_vae.safetensors` |

워크플로 위치는 `C:\ComfyUI\ComfyUI_windows_portable\ComfyUI\user\default\workflows`다.

허용 목록에 포함하지 않는다. 새 모델이나 의존성 다운로드는 범위 밖이다.

## 화면과 상호작용

### 전체 구조

넓은 화면에서는 왼쪽에 좁은 브랜드/메뉴 영역, 가운데에 생성 폼,
오른쪽에 넓은 결과 영역을 둔다. 상단에는 현재 메뉴 제목과 실제 서버 연결 상태를 둔다.
태블릿에서는 메뉴 폭을 줄이고, 모바일에서는 상단 메뉴와 세로 폼/결과로 전환한다.
모든 화면에서 가로 스크롤을 방지한다.

시각 스타일은 아이보리와 흰색 면, 얇은 경계선, 넉넉한 여백, 절제된 그림자,
라임색 선택 상태와 생성 버튼이다. 장식보다 생성 이미지가 주목받도록 한다.
한국어를 기본 언어로 사용한다. 키보드 포커스와 명시적 입력 라벨을 제공하고,
모션 감소 설정을 존중한다.

### 생성 입력

1. 모델 선택: 알아보기 쉬운 모델 이름과 설치/사용 가능 상태.
2. 프롬프트: 충분한 높이의 입력란, 예시 문장, 빈 입력 검증.
3. 사이즈: 비율 도형, 용도, 실제 픽셀 크기, 추천 표시가 있는 선택 카드.
4. 생성 버튼: 요청 중 중복 클릭 방지. 결과 생성 뒤 같은 입력으로 다시 생성 가능.

초기 모델은 Z-Image Turbo, 초기 비율은 정사각형이다.
비율 선택은 정사각형 1:1, 세로 3:4, 가로 4:3, 와이드 약 16:9,
모바일 세로 약 9:16이다. 출력 치수는 모델별 테이블로 관리하며
표준 비율과 픽셀 크기가 약간 다르면 실제 픽셀 크기를 명확히 표시한다.

Z-Image/Krea 초기 크기 후보는 1024×1024, 896×1152, 1152×896,
1344×768, 768×1344다. Qwen은 저장된 워크플로의 안내를 따라
1328×1328, 1104×1472, 1472×1104, 1664×928, 928×1664를 사용한다.
카드 비율 표시는 정확한 픽셀 비율과 일치하게 표시한다.
Z-Image/Krea의 896×1152에는 3:4라고 잘못 표기하지 않고 '세로형'으로 표시한다.
추천 표시는 서비스 기본 선택이라는 의미이며 공식 권장치라고 표현하지 않는다.

### 결과 영역

초기에는 예시 프롬프트를 안내하는 정돈된 빈 상태를 표시한다.
실제 작업을 생성하기 전 가짜 결과나 가짜 생성 기록을 보여주지 않는다.
요청 후 실제 작업 상태와 경과 시간을 표시한다. 실제 스텝 정보가 없으면
백분율을 추정하지 않고 대기 중 / 생성 중 상태만 표시한다.
완료 시 이미지, 모델, 해상도, 사용 프롬프트와 다운로드 버튼을 표시한다.
새 작업이 실패해도 이전에 성공한 결과는 유지한다.

## 모델 프리셋

원시 모델 파일만 바꾸는 방식 대신 모델과 워크플로를 하나의 프리셋으로 관리한다.
이렇게 해야 모델에 맞는 인코더/VAE/샘플러 조합과 사용자의 기존 설정을 보존할 수 있다.

서버가 저장된 세 워크플로를 읽어 실행용 그래프를 구성한다.
프런트엔드 서브그래프, 상위 위젯 값, 내부 연결과 스위치의 실제 적용값을
해석한 뒤, 사용자 입력에 해당하는 프롬프트/가로/세로/생성 시드만 바꾼다.
기존 시드 정책이 randomize이면 새 시드를 만들고 fixed이면 유지한다.
스텝이나 CFG를 '더 적절해 보이는 값'으로 임의 교체하지 않는다.
Qwen의 Lightning 적용 여부와 이에 연결된 스텝/CFG 스위치도 보존한다.
Krea의 프롬프트 확장과 LoRA 활성화 스위치도 보존한다.

구현은 세 가지 확인된 워크플로만 지원한다. 임의 워크플로를 범용 변환하는
편집기를 만들지 않는다. 필요한 노드가 없거나 저장 형식이 지원되지 않으면
해당 프리셋을 사용 불가로 표시하고 원인을 안내한다. 다른 설정으로 몰래 대체하지 않는다.

서버 설정 파일에서 모델별 워크플로 경로와 크기 목록을 관리한다.
후속 모델 추가 시 허용 목록 확인과 프리셋 등록이 필요하다.
파일 존재와 ComfyUI의 지원 노드를 확인하여 실행 가능한 프리셋만 활성화한다.

## 서버 구성과 데이터 흐름

```text
브라우저의 이미지 생성 화면
  → Next.js의 모델/생성/상태/이미지 API
  → 127.0.0.1:8188의 ComfyUI
```

브라우저는 ComfyUI의 주소나 임의 워크플로를 직접 지정하지 않는다.
Next.js Node 런타임에서 파일 접근과 ComfyUI 통신을 처리한다.
기존 프로젝트의 Cache Components 설정을 고려하여 실시간 상태 응답을 캐시하지 않는다.

- 모델 API: 승인된 프리셋, 크기, 준비 상태, 연결 상태 제공.
- 생성 API: 프리셋 ID, 프롬프트, 크기 ID만 받음. 프롬프트는 공백 제거 후
  1~8,000자로 제한하고, 크기와 프리셋은 서버의 허용 목록과 대조.
- 상태 API: ComfyUI 큐/기록을 조회해 작업 상태와 결과를 반환.
- 이미지 API: 이 앱이 만든 작업의 결과만 제공. 임의 로컬 경로나 외부 URL 입력 금지.

생성 요청은 ComfyUI에 큐 등록 후 작업 ID를 즉시 반환한다.
브라우저는 약 2초 간격으로 상태를 확인하고 완료/실패 시 조회를 중단한다.
작업 메타데이터는 프로젝트 내부 `.data`에 저장하고 Git에서 제외한다.
재시작이나 새로고침 뒤에도 마지막 작업 ID로 결과를 다시 확인할 수 있다.
각 생성 요청은 이미지 한 장으로 제한한다.

로컬 설정은 `.env.local`의 `COMFYUI_URL` 및 워크플로 디렉터리 값으로 관리하고,
예제 파일에는 비밀값 없이 기본 경로만 기록한다.
이미지 파일은 ComfyUI 결과에서 확인된 파일명/서브폴더/타입 조합만 중계한다.

## 실패 처리

- ComfyUI 연결 실패: 연결 끊김 표시와 재확인 동작.
- 누락 모델/노드/워크플로: 해당 모델 비활성화 및 구체적 원인 안내.
- 프롬프트 누락/비허용 크기: 요청 전후 검증, 큐에 넣지 않음.
- ComfyUI 검증 오류: 사용자용 실패 안내, 자세한 원인은 서버 로그에 기록.
- 생성 오류/VRAM 부족: 실패 상태와 다시 시도 안내. 임의 설정 변경이나 자동 재생성 없음.
- 통신 실패: 즉시 새 작업을 만들지 않고 기존 작업 ID로 상태 재확인.

## 검증과 완료 기준

- 현재 Next.js 번들 문서를 기준으로 구현하고 타입 검사와 프로덕션 빌드를 통과.
- 입력 검증과 워크플로 변환의 의미 있는 단위 검사:
  프롬프트/사이즈 교체, 기존 스텝/CFG/스위치 보존, 비허용 값 거부.
- 실행 가능한 세 프리셋의 ComfyUI 그래프 검증 및 파일/노드 확인.
- 실제 Z-Image 기본 크기 한 장을 생성해 큐 등록 → 상태 → 결과 → 다운로드까지 확인.
- 데스크톱과 모바일 화면에서 메뉴, 입력, 결과, 키보드 접근과 오버플로 확인.
- 기존 다른 사이트와 겹치지 않도록 로컬 미리보기는 기본 3001 포트 사용.
- 확인하지 못한 모델의 실제 생성 성능은 검증했다고 보고하지 않음.

## 이번에 수정할 영역

- `app/page.tsx`, `app/layout.tsx`, `app/globals.css`: 브랜드와 기본 화면.
- `components/`: 메뉴, 생성 폼, 크기 카드, 결과 표시.
- `lib/`: 모델 설정, 워크플로 변환, ComfyUI 통신, 작업 메타데이터.
- `app/api/`: 모델 조회, 생성, 상태, 결과 이미지 처리.
- 검사 스크립트, `.env.example`, `.gitignore`, 실행 방법을 담은 README.

사용자의 기존 ComfyUI 워크플로와 모델 파일은 수정하지 않는다.
